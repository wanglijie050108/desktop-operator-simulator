# changelog 记录时机调整与目录清理

## 元信息

- 日期：2026-10-05
- 状态：已完成
- 环境：Windows 11；仅改 AI 协作规范与 changelog 目录，无代码改动

## 目标

- 消除“每个中间步骤都改写 changelog”造成的冗长与噪声。
- 清空今天之前的 changelog 条目，使目录只保留当前提交周期的记录。

## 分析与决策

- 旧规范的根因是三处叠加：`SKILL.md` §2.7“首次修改仓库前创建记录”、§8.3/§8.8“任务开始时创建、
  每个有意义操作后增量更新、同一文件持续更新”，`changelog/README.md`“更新时机”与 `AGENTS.md`
  同措辞。记录因此被当作逐步操作流水账反复回写。
- 采用方案：changelog 定义为**提交时产物**——提交前写一次，与改动一起提交；内容聚焦“分析了
  什么、结论是什么、实际做了什么、验证状态如何”，用密集事实代替流水账；不产生提交的纯问答
  任务不必记录，除非结论需被后续工作复用。
- 未放宽：验证状态词表、脱敏与内容边界、模板格式、`docs/08` 同步要求保持原样。
- 目录策略改为**不再保留历史归档层**：23 个 2026-10-05 之前的条目从工作区移除。它们全部已提交，
  可从 git 历史取回；需长期留存的关键事实由 `docs/08`（里程碑状态、精确数字、CI run id、提交
  哈希）与 `docs/06`（技术决策与停止条件）承担，不再依赖 changelog 条目驻留。

## 文件变更

- `.trae/skills/human-operation-simulator-guardrails/SKILL.md`：§2.7、§10.8 改为“提交前写入”；
  §8 整节改写为 10 条提交时规则（含“不逐步改写”“用密集事实代替操作流水账”）。
- `changelog/README.md`：“强制范围”改为按提交记录；“更新时机”改为提交前写一次；“目录结构”与
  “读取约定”去掉归档层；“滚动归档策略”改为“历史清理策略”，新增“删除前必须确认已提交”。
- `AGENTS.md`、`README.md`：入口措辞同步为“提交前记录一次”。
- 删除 `changelog/2026-09-24..2026-10-04-*.md` 共 23 个文件（删前逐个经 `git ls-files` 确认已提交）。

## 风险与限制

- 历史叙事不再随仓库分发；关键事实依赖 `docs/08`/`docs/06` 承载，若某细节只存在于被删条目中，
