# AI 工作记录规范

`changelog/` 用于持久化 AI 在本仓库中的分析、修改、调试、联调、测试和环境操作，
使更换机器或助手后仍能恢复关键上下文并复核结果。

## 目录结构

本目录只保留**当前提交周期**的记录：

- `README.md`：本规范与下列索引。
- 独立记录：一天一个文件，一条记录对应一个逻辑任务，按下方模板记录。
- 历史记录：不长期保留在工作区。更早的条目按“历史清理策略”移出工作区，需要时从
  git 历史取回。

当前记录：

- `2026-10-05-wechat-spike-b-readiness.md`：微信 Spike B 前置可行性核对。
- `2026-10-05-changelog-policy-and-cleanup.md`：changelog 记录时机调整与目录清理。

## 读取约定

任务开始时只需读：本文件 → 上表索引 → 与任务最相关的近期记录。
不要遍历历史条目；需要旧条目时先
`git log --diff-filter=D --name-only -- changelog/` 找到移除它的提交，
再用 `git show <commit>:changelog/<原文件名>` 取回。

## 强制范围

按**提交**记录：一条记录对应一个逻辑任务，在提交前写好并与改动一起提交。

- 有提交的任务必须记录：需求/架构/代码/故障分析、文件增删改、依赖与配置变更、
  构建/测试/联调/部署/回滚、失败尝试与阻塞调查。
- 没有提交的纯问答任务不必记录；只有结论需要被后续工作复用时才补一条。

## 文件命名

每个逻辑任务使用一个文件：

```text
YYYY-MM-DD-short-topic.md
```

`short-topic` 使用简短、稳定的英文 kebab-case。当天同名任务使用
`YYYY-MM-DD-short-topic-2.md`、`-3.md` 递增，不覆盖旧记录。

## 更新时机

1. 在**提交前**写一次，并与它描述的改动一起 `git add`。
2. 一条记录只描述一个逻辑任务，不在每个中间步骤反复改写。
3. 内容聚焦“分析了什么、得出什么结论、实际做了什么、验证状态如何”，用几条密集的
   事实说明，不写逐步操作流水账：不重述 diff、不逐条列举琐碎改动、不粘贴命令原始输出。
4. 提交前对照实际 diff、命令结果与 `git status` 做一次复核。

记录必须在改动仍可核实时写出：不要把多个任务事后补写成无法核实的事后总结。

## 状态词

验证项只使用：

- `PASSED`：已执行且通过。
- `FAILED`：已执行但失败。
- `NOT_EXECUTED`：未执行，并说明原因。
- `BLOCKED`：受明确外部条件阻塞，并说明解除条件。

## 模板

```markdown
# <任务标题>

## 元信息

- 日期：YYYY-MM-DD
- 状态：进行中 / 已完成 / 受阻
- 环境：操作系统、关键运行时；未知项写“未确认”

## 目标

- 本次任务要达成的可验证结果。

## 上下文与证据

- 阅读的文档、代码、配置和历史记录。
- 与任务有关的现状，不粘贴大段原文或原始日志。

## 分析与决策

- 可复核的判断、依据、备选方案和取舍。
- 记录最终采用或拒绝方案的原因。

## 操作记录

1. 执行了什么操作。
   - 结果：成功 / 失败 / 部分完成。
   - 影响：涉及的文件、模块或环境。

## 文件变更

- `path/to/file`：改动内容及原因。

## 验证

| 命令或检查 | 状态 | 结果 |
|---|---|---|
| `<command>` | PASSED / FAILED / NOT_EXECUTED / BLOCKED | 简明结果或原因 |

## 问题与处理

- 现象：
- 根因：
- 处理：
- 结果：

没有问题时写“无”。

## 风险与限制

- 尚未验证的环境、残留风险和后续触发条件。

## 最终结果

- 已完成的结果、未完成项和下一步。
```

按任务删去完全不适用的空项，但不得删除“验证”“风险与限制”和“最终结果”。
各节写要点即可：模板是格式约束，不是必须写满的清单，宁少勿冗。

## 历史清理策略

1. 当前提交周期之外的记录不保留在工作区：清理时从 `changelog/` 移除，作为一次提交的一部分。
2. 清理只作用于工作区，不改变 git 历史：被移除的条目仍可用
   `git show <commit>:changelog/<原文件名>` 取回。
3. 清理前必须确认目标文件**已提交**（`git ls-files` 可查到）；未提交的条目不得直接删除。
4. 需要长期留存的关键事实不得依赖 changelog 条目驻留，应写入长期文档：
   里程碑状态、验证证据、精确数字与 CI run id 记入 `docs/08-development-status.md`，
   技术决策与停止条件记入 `docs/06-decisions-and-risks.md`。
5. 清理属于文档整理任务，其本身仍需一条记录说明清理范围。

## 内容边界

记录事实、证据摘要、决策理由和可复现结果，不记录：

- 模型隐藏思维链、逐字内部推理或无结论的自言自语。
- 密钥、令牌、Cookie、账号、个人信息和真实聊天正文。
- 未脱敏截图、数据库、浏览器 Profile 或大段原始日志。
- 与任务无关的本机信息。

敏感信息只记录为“已配置”“已脱敏”或“未提供”。命令输出较长时记录关键结论及
必要错误摘要，不复制完整输出。
