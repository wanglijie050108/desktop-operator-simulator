# AI 工作记录规范

`changelog/` 用于持久化 AI 在本仓库中的分析、修改、调试、联调、测试和环境操作，
使更换机器或助手后仍能恢复关键上下文并复核结果。

## 强制范围

以下任务即使没有代码改动，也必须记录：

- 需求、架构、代码或故障分析。
- 文件创建、修改、删除或格式化。
- 依赖安装、配置和环境变更。
- 构建、测试、联调、运行、部署和回滚。
- 失败尝试、阻塞调查和只读验证。

## 文件命名

每个逻辑任务使用一个文件：

```text
YYYY-MM-DD-short-topic.md
```

`short-topic` 使用简短、稳定的英文 kebab-case。当天同名任务使用
`YYYY-MM-DD-short-topic-2.md`、`-3.md` 递增，不覆盖旧记录。

## 更新时机

1. 任务开始、完成初步上下文检查后创建记录。
2. 每次有意义的分析结论、文件操作、命令、失败或决策后增量更新。
3. 联调或验证完成后立即记录状态和关键结果。
4. 任务结束前对照实际 diff、命令结果和 Git 状态完成最终复核。

不要把记录集中补写成无法核实的事后总结。

## 状态词

验证项只使用：

- `PASSED`：已执行且通过。
- `FAILED`：已执行但失败。
- `NOT_EXECUTED`：未执行，并说明原因。
- `BLOCKED`：受明确外部条件阻塞，并说明解除条件。

## 模板

```markdown
# <任务标题>

## 元信息

- 日期：YYYY-MM-DD
- 状态：进行中 / 已完成 / 受阻
- 环境：操作系统、关键运行时；未知项写“未确认”

## 目标

- 本次任务要达成的可验证结果。

## 上下文与证据

- 阅读的文档、代码、配置和历史记录。
- 与任务有关的现状，不粘贴大段原文或原始日志。

## 分析与决策

- 可复核的判断、依据、备选方案和取舍。
- 记录最终采用或拒绝方案的原因。

## 操作记录

1. 执行了什么操作。
   - 结果：成功 / 失败 / 部分完成。
   - 影响：涉及的文件、模块或环境。

## 文件变更

- `path/to/file`：改动内容及原因。

## 验证

| 命令或检查 | 状态 | 结果 |
|---|---|---|
| `<command>` | PASSED / FAILED / NOT_EXECUTED / BLOCKED | 简明结果或原因 |

## 问题与处理

- 现象：
- 根因：
- 处理：
- 结果：

没有问题时写“无”。

## 风险与限制

- 尚未验证的环境、残留风险和后续触发条件。

## 最终结果

- 已完成的结果、未完成项和下一步。
```

按任务删去完全不适用的空项，但不得删除“验证”“风险与限制”和“最终结果”。

## 内容边界

记录事实、证据摘要、决策理由和可复现结果，不记录：

- 模型隐藏思维链、逐字内部推理或无结论的自言自语。
- 密钥、令牌、Cookie、账号、个人信息和真实聊天正文。
- 未脱敏截图、数据库、浏览器 Profile 或大段原始日志。
- 与任务无关的本机信息。

敏感信息只记录为“已配置”“已脱敏”或“未提供”。命令输出较长时记录关键结论及
必要错误摘要，不复制完整输出。
