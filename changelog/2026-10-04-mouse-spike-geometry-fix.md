# 修复鼠标 Spike 的验证几何假设（贴边坐标 → 比例探测点）

## 元信息

- 日期：2026-10-04
- 状态：已完成（代码与跨平台验证）；实机复测待执行
- 环境：Windows 11 build 26200；Python 3.11.6、pywinauto 0.6.9

## 目标

- 修复目标机 1 轮自检失败 `MOUSE_CLICK_CARET_MISMATCH` 的根因，使鼠标 Spike 能在真实
  记事本窗口上完成验证，且验证不依赖任何手工标定的像素偏移。

## 上下文与证据

- 用户在**自己的交互式会话**执行 `npm run test:spike:m0:notepad-mouse`（1 轮）：
  `{"passed": false, "successCount": 0, "errorCounts": {"MOUSE_CLICK_CARET_MISMATCH": 1}}`，
  报告 `notepad-mouse-spike-20261004-072916813161.json`。
- 同一环境下的关键事实：本 Agent 会话的 `pywinauto UIA` 可枚举窗口数为 **0**（`EnumWindows`
  为 650），因此无法由本会话完成实机验证；用户会话中 UIA 正常，Spike 已能启动并定位记事本。
- 用户观察到的现象：记事本被打开、文本出现、随后被全选替换、最后出现一个 `[`。
- 由此可判定：窗口定位、UIA 读回、真实指针移动、剪贴板写入**全部正常**（`MOUSE_MOVE` 断言
  已通过，失败发生在点击之后），失败只出在"点击落点"。
- 根因：原实现把点击点写成相对 `Document` 控件矩形**左上角的固定像素偏移** (4,8)。Windows 11
  记事本的该矩形可能包含标签栏/菜单行（甚至等于整个窗口），于是 (4,8) 落在**非文本区域**，
  点击不移动插入点，`[` 被插在粘贴后的原位。

## 分析与决策

- 不再标定像素，改用**控件矩形的比例**作为探测点：只要比例点落在编辑区内即可，与其左上角
  究竟从哪开始无关。
- 让文档**高于且宽于**编辑区（30 行 × 130 字符，共约 3.9 KB，未超 4 KB 剪贴板上限），
  保证每个探测点下方必有文字，横向探测点也落在行内。
- 用**单调性**代替"必须等于 0"：同一 x 上 35% 与 75% 两处点击的插入位置必须满足
  `索引(35%) < 索引(75%)`，这比"等于行首"更稳健，且更能证明"插入点跟随鼠标"。
- 坐标兜底路径改为**等价性断言**：把 75% 那个点换算成窗口相对坐标再点一次，其插入位置必须与
  语义点击**完全相同**（比"等于 0"更精确地证明两条路径一致）。
- 拖拽增加**"真子串"**断言：重置粘贴会把全文放进剪贴板，因此空选区会让长度等于全文，
  要求选区非空、是文档子串且**严格短于**全文。
- 报告新增**诊断数据**：实测窗口/控件矩形、三个点击的插入位置、选区长度、三次滚动的标记行号
  （只含几何与整数，不含文档文本），使下一次失败无需再让用户在真机上多跑一轮。
- 粘贴与点击后各等待 0.1 s，避免注入输入被吞。

## 问题与处理

- 现象：实机自检报 `MOUSE_CLICK_CARET_MISMATCH`。
  - 根因：点击点相对控件矩形左上角固定偏置，落在非文本区域。
  - 处理：改为比例探测点 + 单调性/等价性断言，并把几何写入报告。
  - 结果：待实机复测确认。
- 现象：本 Agent 会话无法运行实机 Spike（UIA 枚举 0 个窗口）。
  - 根因：本会话进程为受限令牌/受限 job，UIA 无法跨进程遍历桌面，且其启动的 GUI 进程拿不到
    可见窗口。
  - 处理：保持实机步骤由用户的交互式会话执行；文档已说明该限制。
  - 结果：BLOCKED（仅限本会话）。

## 风险与限制

- 比例常量（30%/35%/75%/40%/70%/20%）按典型记事本窗口尺寸选定；若某台机器上编辑区明显偏离，
  报告中的 `caretIndices` 相等会直接暴露"点击没落到文本上"，据此再调比例。
- 实机验证仍依赖 Windows 11 记事本的可访问性行为；键盘 Spike（Spike A）与本次改动无关。
- 新报告字段只含几何与索引，不含任何文档文本；该性质由单元测试断言。
