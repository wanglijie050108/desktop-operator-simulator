# 公众号测试号是否适用与个人微信号测试风险分析

## 元信息

- 日期：2026-11-17
- 状态：已完成（只读分析交付；无代码、文档、契约改动）
- 环境：Windows 11；未访问或注册任何微信平台账号
- 分支：`feature/pywinauto1`

## 目标

- 判断微信公众平台“测试号”（sandbox）能否用于本项目的微信桌面自动化验证。
- 评估使用个人微信号做 Spike B/M2 测试的风险与可行替代方案。

## 上下文与证据

- 项目对象是 **Windows 微信桌面客户端**，通过 pywinauto/UIA 操作窗口、输入框和消息区。
- 用户提供的链接是微信公众平台接口测试号（`mp.weixin.qq.com/debug/cgi-bin/sandboxinfo`），
  属**公众号**开发测试号：提供 appID/appsecret，并要求配置服务器 URL、Token 与域名，
  用于接收公众号消息推送。
- `docs/07` §8 明确禁止使用个人主账号与真实工作聊天；要求独立测试账号与受信任
  测试联系人。
- `docs/06` R-01 的备选方案是“改用另一可访问聊天工具或课程专用消息页”。

## 分析与决策

### 公众号测试号不适用于本项目

- 它不是一个可登录的“第二微信号”，不会出现在微信桌面客户端里，因此无法用于
  UIA 控件定位、窗口激活、剪贴板发送或消息读回。
- 它要求公网可达的 URL + Token，属于服务器回调模型；本项目不实现公众号服务器，
  也不需要通过它收发消息。
- 申请本身不难（通常即时开通），但对 Spike B/M2 没有帮助，不建议投入时间。

### 用个人微信号测试的风险

1. **账号风险（不可完全消除）**：微信用户协议限制自动化/外挂类操作。UI 自动化
   比注入/hook 温和，但仍存在被风控、限制登录或封号的可能。缓解：低频、仅测试
   账号、遇验证码立即人工接管、不在主号上跑。
2. **误发风险**：Spike 会真实发送消息。工具已做会话标题双重校验与失败关闭，
   但定位器配错时仍可能发到当前打开的会话。缓解：只停留在“文件传输助手”或
   专用测试会话，绝不停留在真实联系人会话上运行。
3. **隐私风险**：Agent 会读取当前会话可见文本；截图/日志虽已脱敏，但测试机上
   存在真实聊天记录仍是暴露面。缓解：专用 Windows 用户、只打开测试会话、
   不在测试账号中放真实联系人。

### 推荐方案

- **Spike B 阶段**：直接用自己的账号 + “文件传输助手”即可。它不发给任何真人，
  足以验证“发送 + UIA 读回”；不需要第二个账号。
- **M2 真实双端收发的阶段**：再准备一个专用小号（独立手机号）与受信任测试联系人；
  不要把主号作为 Agent 登录账号。
- 若无条件准备小号且 R-01 判定微信不可用，按 `docs/06` 切换到企业微信或课程
  专用消息页，但这是演示对象变更，需要导师确认。

## 风险与限制

- 未实测微信对 UI 自动化的风控强度；“存在账号风险”是条款与常见实践判断，
  不是实测结论。
- 文件传输助手能否被 UIA 稳定读取仍需 Spike B 取证验证。
- 专用小号的注册条件（手机号、实名、PC 登录限制）因地区与账号状态而异，未核实。

## 最终结果

- 公众号测试号不适用于本项目，不必申请。
- 建议 Spike B 使用本人账号的“文件传输助手”；M2 再引入专用小号。
- 明确账号、误发、隐私三类风险与对应缓解措施。
