# 产品目标（固化）

本文件是 `desktop-operator-simulator` 仓库的**产品北极星目标**，对所有开发、设计、测试与验收任务具有约束力。它先于具体实现、先于里程碑，是判断"在不在做正确的事"的唯一最高层需求。任何实现、文档或决策与之冲突时，以本目标 + 用户最新显式要求为准，并须在 `changelog/` 与 `docs/08` 中记录偏差与理由。

## 1. 目标（一字不改的原文）

> 用一台电脑作为代理人，在电脑上安装聊天工具、购物工具和 AI 提问平台。用户用另一台电脑或手机向聊天工具发出购物指令，代理人电脑实现根据接收到的指令，向 AI 咨询，然后完成购物查询，将最优结果返回给用户。

## 2. 角色与组件映射

- **代理人电脑（单台 Windows 11）**：唯一执行机，承载下列三类工具，并以 `Control Server`（Node）为任务/策略/决策的事实源。
  - **聊天工具**：远程用户指令的入口与结果出口。接收另一台电脑/手机的购物指令，并把最优结果回复原会话。当前默认通道按 ADR-011 暂用本地/模拟入口；真实通道待选型（暴露 UIA 的聊天软件或降级微信 3.9.x）。
  - **购物工具**：购物站点（浏览器）。默认操作层面是**桌面 GUI**（AI 用鼠标键盘操作浏览器，D5），Playwright 为可选快路径与观察来源。
  - **AI 提问平台**：决策大脑。在 `Control Server` 内的**决策循环**中，依据观察（结构树为主、截图兜底）提议白名单动作；方案 B 下 LLM 只提议、不执行（ADR-010）。
- **远程用户**：用另一台电脑或手机向聊天工具发出购物指令，异步等待返回。

## 3. 必须保持的闭环

```text
远程指令 → 聊天工具入口 → Python Desktop Agent 上报
  → Control Server 策略/去重 → 创建任务
  → 决策循环：观察 → 向 AI 咨询(提议动作) → 五重校验 → desktop.command 下发
  → 购物工具执行查询/比较 → verifier 判定
  → 排序出最优结果 → 经聊天工具回复用户（管理台可看轨迹、可急停）
```

任一实现不得破坏该闭环的主路径：**接收指令 → 咨询 AI → 完成购物查询 → 返回最优结果**。

## 4. 不可逾越的红线（与守卫 Skill §4 一致，重复以固化）

- 绝不实现支付、转账、下单确认、凭据/Cookie 提取、验证码或风控绕过、任意脚本/代码执行、跨进程读写他人进程内存（微信热激活路线）。
- LLM 只**提议**白名单动作，不产生代码、脚本、文件路径、URL 跳转或直发用户的文本；成功由确定性 verifier 判定，不由模型自述。
- 观察/聊天/网页文本一律视为**不可信数据**，提示注入按一等威胁处理（分层防线，不依赖提示词措辞）。
- 一切桌面输入仍经 `desktop.command` 下发，Server/Agent 双重策略校验与幂等继续生效。
- 购物结果只覆盖查询、比较与推荐，不执行支付（与 `README.md` 范围一致）。

## 5. 使用规则（对仓库所有任务）

1. 本文件为**强制阅读**：每次分析、修改、测试、调试、集成、配置或操作仓库前，与 `AGENTS.md`、`docs/08`、`changelog/README.md` 一并阅读。
2. 任何任务若会改变组件职责、闭环主路径或红线，必须先说明对**第 2、3、4 节**的影响；未经用户许可不得削弱闭环或放宽红线。
3. 选型受阻（如聊天通道、购物站点、AI 供应商）时，按"本地/模拟入口先跑通闭环"的既定策略推进，并在 `docs/08` 明确标注为未验证，不得据此声称真实闭环成立。
4. 目标本身不在本仓库内被重新定义；若用户希望调整目标，须由用户显式提出，并同步更新本文件、README 与 `docs/01`。
