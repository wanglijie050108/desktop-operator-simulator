# 需求与范围

## 1. 项目目标

在一台 Windows 代理机上运行软件代理，通过模拟人工操作完成：

- 接收另一台电脑或手机发来的自然语言指令。
- 操作 AI 问答页面，获取辅助分析结果。
- 操作购物网站，搜索、筛选、比较商品。
- 将结构化结果回复给发起用户。
- 展示鼠标、键盘、剪贴板和窗口自动化能力。

项目重点是“没有业务 API 时如何可靠、安全地驱动既有软件”，而不是开发通用 RPA 平台。

**AI 的角色（2026-10-10 修订，见 [`14-plan-b-design.md`](14-plan-b-design.md) 与 ADR-010）**：
代理需要一个能应对未见界面的决策层。AI（LLM）在 Control Server 内驱动
observation → reasoning → action 循环，依据结构树（UIA/DOM）观察——截图与多模态视觉
为兜底——自主决定下一个白名单桌面动作。**AI 只提议，不执行**：提议必须通过与固定工作流
完全相同的 Schema、动作白名单、参数范围与策略校验，成功与否由确定性 verifier 判定。
确定性工作流保留为"有把握时走的快捷路径"与演示兜底，不再是唯一执行路径。

## 2. 角色

| 角色 | 职责 |
|---|---|
| 指令用户 | 通过聊天工具发送查询，查看结果，确认高风险步骤 |
| 系统管理员 | 配置受信任联系人、站点、执行限额，查看日志和停止任务 |
| 桌面代理 | 监听消息、驱动 Windows 应用、回复结果 |
| 浏览器执行器 | 驱动 AI 与购物网页，提取结构化结果 |

## 3. MVP 范围

### 3.1 必须实现

- 微信桌面端单一受信任联系人收发消息。
- 命令前缀识别，例如 `#助手`，防止普通聊天被误执行。
- AI 问答：提交问题并返回回答文本。
- 商品搜索：关键词、最高价格、候选数量三个基础条件。
- 商品比较：名称、价格、店铺、销量/评价摘要、商品链接。
- 任务状态：等待、执行中、待确认、成功、失败、取消。
- 任务超时、重试、截图留证和紧急停止。
- 管理员可查看任务记录，但敏感信息必须脱敏。

### 3.2 可延期

- 多联系人、多聊天软件。
- 将商品加入购物车。
- EDA、机械设计等专业软件适配。
- 云端部署、多代理机调度。
- 通用可视化流程编辑器。

> 原列为可延期的“图片识别/OCR 兜底”已移入本期范围（见 3.1 与 FR-11）：
> 结构树为主路径，截图 + 多模态视觉为兜底观察手段。

### 3.3 明确不做

- 支付、转账、红包、下单确认。
- 绕过验证码、风控、登录保护或网站反自动化措施。
- 自动保存或导出账号密码、Cookie、支付信息。
- 接受任意 shell、脚本、文件路径或网页 JavaScript 指令。
- 未经确认发送群消息、删除数据、修改账号或系统设置。

## 4. 典型用例

### UC-01 AI 问答

输入：`#助手 问AI：解释什么是零信任网络，200字以内`

输出：回答正文、来源为哪个 AI 页面、执行耗时。页面不可用时返回明确失败原因，不编造回答。

### UC-02 商品搜索与比较

输入：`#助手 搜索 300元以内的无线鼠标，选3款，优先静音和办公`

流程：

1. 识别商品、预算、数量和偏好。
2. 用户输入不完整时仅询问必要信息。
3. 在允许的购物网站执行搜索。
4. 提取候选商品并按可解释规则排序。
5. 返回三款商品的关键属性、链接与排序依据。

### UC-03 取消任务

输入：`#助手 取消 <任务短号>`

要求：停止后续操作，释放鼠标/键盘控制，保留已完成步骤和取消原因。

## 5. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-01 | 只处理受信任联系人且带命令前缀的消息 | P0 |
| FR-02 | 相同消息不得重复创建任务 | P0 |
| FR-03 | **策略校验**必须确定性：动作类型、参数与目标必须经白名单与策略双重校验；**执行路径**可由确定性工作流或有界决策循环完成 | P0 |
| FR-04 | 支持 UIA、DOM 和坐标兜底三类定位 | P0 |
| FR-05 | 记录每一步开始、结束、耗时和结果 | P0 |
| FR-06 | 支持超时、有限重试和取消 | P0 |
| FR-07 | 商品结果必须携带采集时间与原始链接 | P0 |
| FR-08 | 支持管理员紧急停止和暂停接单 | P0 |
| FR-09 | 提供本地管理页面 | P1 |
| FR-10 | UI 变化后能通过适配器版本隔离修复 | P1 |
| FR-11 | 决策主路径使用结构树（UIA/DOM）观察，截图与多模态视觉作为兜底观察手段 | P0 |
| FR-12 | AI 只能提议白名单动作，不得产生代码、脚本、文件路径、URL 跳转或直发用户的文本 | P0 |
| FR-13 | 任务成功由确定性 verifier 判定，AI 自述完成不构成成功 | P0 |
| FR-14 | 决策循环必须有界：每任务设轮次、wall-clock 与 token 预算，超限转 `WAITING_FOR_HUMAN` | P0 |
| FR-15 | 决策可留痕与可复现：每轮 observation 摘要、模型输出、校验结论与执行结果持久化并脱敏，支持轨迹回放 | P0 |
| FR-16 | 观察内容（网页、聊天正文）按不可信数据对待，不得因其中的指令改变策略判定 | P0 |

## 6. 非功能需求

- **可靠性**：MVP 标准场景成功率不低于 90%，失败必须可诊断。
- **性能**：接收消息后 3 秒内创建任务；普通搜索在 90 秒内完成。
- **可恢复性**：进程重启后，未完成任务标记为中断，不自动重复高风险动作。
- **可维护性**：站点和应用定位规则独立于工作流；禁止散落固定坐标。
- **可观测性**：结构化日志统一包含 `taskId`、`stepId`、`adapter`；决策循环另需可回看的
  决策轨迹（每轮 observation 摘要、模型输出、校验结论、执行结果）。
- **可复现性**：非确定性决策必须可用录制的轨迹回放复现，用于回归测试与演示兜底。
- **成本可控**：每任务决策轮数与 token 消耗有硬预算，并在统计中可见。
- **安全性**：服务默认只监听 `127.0.0.1`；远程访问必须通过明确认证。
- **隐私性**：截图按任务保存并设置保留期；日志不记录聊天历史全文和凭据。

## 7. 关键假设与待验证项

编码前必须在目标 Windows 机器完成以下 Spike：

1. 微信目标版本的消息列表和输入框能否由 UIA3 稳定识别。
2. 购物网站是否允许 Playwright 正常登录和检索，是否频繁触发验证码。
3. AI 页面是否能用稳定 DOM 定位提交框和回答区。
4. 代理机被自动化期间是否允许用户同时操作；MVP 建议独占桌面会话。
5. 学校演示网络是否能稳定访问目标站点。
6. **目标软件的观察层是否可用**：结构树（UIA/DOM）能否取到足够节点支撑决策；不能时
   截图 + 多模态视觉兜底是否可用（FR-11）。
7. **决策循环的可终止性与成本**：在目标任务上实测轮次、耗时与 token 消耗，据此冻结
   FR-14 的预算数值。

任何一项失败都应调整适配对象，不应通过绕过安全机制解决。
