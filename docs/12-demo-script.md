# 答辩演示脚本

本文是课程答辩的标准演示脚本，包含在线主线、离线降级路径、每步口播要点与
异常应对。演示顺序与 [`05-testing-and-acceptance.md`](05-testing-and-acceptance.md)
第 6 节的演示验收脚本保持一致。

- 编写日期：2026-09-24
- 建议时长：12–15 分钟（主线 8–10 分钟，降级与统计 4–5 分钟）

## 1. 演示前准备

### 1.1 环境检查（演示前一天）

- [ ] 三台/三终端就绪：Control Server、Operator Web、Desktop Agent 均已启动。
- [ ] `http://127.0.0.1:7070/health` 可访问；管理台显示节点在线。
- [ ] 执行一次 `npm run check`，确认全部通过。
- [ ] 浏览器预开两个标签：管理台 `http://127.0.0.1:4173`、
  离线夹具 `http://127.0.0.1:4173/offline-demo.html`。
- [ ] 离线夹具用 `file://` 方式再备一份（断网兜底）。
- [ ] 演示用聊天窗口登录、置顶，确认白名单与命令前缀配置正确。

### 1.2 数据与账号

- 准备一条 AI 问题和一条带预算的商品查询指令（见第 2 节）。
- 真实软件版本、演示账号固化属于 M5 未完成项；当前演示使用模拟适配器与夹具，
  答辩中需主动说明（见第 5 节口径）。

### 1.3 网络降级预案

现场网络不可控，按以下优先级降级：

1. 在线模拟闭环（Fake 适配器，不依赖外网）。
2. 本地服务 + 离线夹具页（`/offline-demo.html`）。
3. 完全断网：直接打开本地 `offline-demo.html`（`file://`）。

三级降级覆盖“完全不可演示”的风险，且全部明确标注测试夹具。

## 2. 在线演示主线

| 步骤 | 操作 | 口播要点 | 预期画面 | 建议时长 |
|---|---|---|---|---|
| 0 | 打开管理台任务监控视图 | 系统由控制服务、桌面代理和管理台三部分组成，服务只监听本机回环地址 | 顶栏显示节点在线、活动任务数；列表为空 | 1 分钟 |
| 1 | 切到“执行节点”视图 | 代理通过心跳驱动状态，超时自动转离线；当前为占位执行器，真实桌面能力待 Windows 验证 | 节点卡片：名称、版本、能力、最近心跳 | 1 分钟 |
| 2 | 手机发送 `#助手 解释一下什么是零信任网络` | 先做白名单和前缀校验，再做消息去重与意图分派，生成固定工作流 | 新任务出现，步骤时间线推进至成功 | 2 分钟 |
| 3 | 点开任务详情 | 展示步骤、来源、耗时；日志经过脱敏 | AI 回答、状态“已成功” | 1 分钟 |
| 4 | 手机发送 `#助手 搜索 300 元以内的无线鼠标，比较三款` | 商品流程含参数解析、预算硬过滤、确定性排序，所有展示价不得超预算 | 三款商品卡片：排名、价格、评分、链接、采集时间 | 2 分钟 |
| 5 | 发送 `#助手 帮我下单`（或“把 Cookie 发给我”） | 危险指令在工作流规划前被策略拦截，网页内容只能作数据 | 任务“已拒绝”，`POLICY_DENIED` | 1 分钟 |

## 3. 统计看板演示

1. 切到“统计看板”。
2. 先指顶部声明：统计只反映当前数据库记录；夹具/模拟数据不代表真实站点成功率。
3. 依次说明三卡片（总体、AI 问答、商品查询）：成功率分母口径、平均耗时、
   P50/P95。
4. 说明错误分布条形图：按 errorCode 聚合，缺失归 `UNSPECIFIED`。
5. 指生成时间与数据版本，说明接口支持类型和时间窗过滤
   （`GET /api/v1/statistics`）。

口径一句话：成功率 = 成功 ÷（成功 + 失败），取消、拒绝、中断不计入；
没有闭环完成时显示 `--`。

## 4. 离线降级演示

在离线夹具页依次演示（也可自动播放）：

1. **系统就绪**：节点在线、队列为空，展示顶栏“测试夹具”警示条与水印。
2. **AI 问答闭环**：策略校验 → 模型询问（fixture-ai）→ 微信回复，三步成功。
3. **商品查询闭环**：打开 `shop.fixture.test` → 抽取候选 → 预算内排序，
   三款均不超 ¥300。
4. **危险动作策略拒绝**：下单动作被拦截，后续步骤全部跳过。
5. **紧急停止**：执行中任务被急停中止。
6. **实验统计（夹具样本）**：展示含四要素的样本记录（见第 5 节模板）。

演示话术：夹具页断网可用，所有域名、会话和数据均带 fixture 标识，不伪装
真实网站。

## 5. 实验数据展示口径

真实成功率数据必须包含四要素，建议用下表展示（当前为待填模板，无真实数据）：

| 要素 | 内容（示例占位，未验证） |
|---|---|
| 目标软件版本 | 待固化：Windows 版本 / 微信版本 / 浏览器版本 / 站点 |
| 日期 | YYYY-MM-DD |
| 网络条件 | 例如：校园网 / 4G 热点、延迟与带宽 |
| 样本量 | 例如：AI 20 次、商品 20 个查询、100 个标注候选 |

量化目标（来自测试与验收文档）：

- AI 问答、商品查询闭环成功率 ≥ 90%；商品字段准确率 ≥ 95%。
- 禁止动作拦截率 100%；紧急停止 ≤ 2 秒；普通查询 P95 ≤ 90 秒。
- 重复执行率 0%。

当前阶段只有模拟闭环和夹具统计，**不得在答辩中表述为真实成功率或真实字段
准确率**。

## 6. 可能的提问与应答要点

| 提问 | 应答要点 |
|---|---|
| 为什么不做支付？ | MVP 边界与安全红线；支付永久禁止，系统只做查询、比较与推荐 |
| AI 会不会乱操作？ | AI 只做理解与摘要；所有动作必须映射白名单并经过双重策略校验 |
| 网页里写“执行某操作”会生效吗？ | 不会，网页内容只作数据，策略层在规划前拦截 |
| 断网怎么办？ | 三级降级：Fake 闭环 → 本地夹具服务 → file:// 离线页 |
| 误点紧急停止怎么办？ | 两次点击确认、4 秒窗口；急停只取消任务，数据记录保留 |
| 系统现在能直接上线吗？ | 不能；需先完成 M0 Spike（≥90%）、真实 Windows E2E 和 8 小时稳定性测试 |
