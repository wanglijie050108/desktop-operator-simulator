# 技术决策与风险

## 1. 技术选型决策

### ADR-001：采用 C# Agent + Node Control Server

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 全 C# | Windows 集成统一 | Web 自动化和前端迭代较慢，未体现 Node.js 学习目标 | 不选 |
| 全 Node.js | 单语言、Playwright 直接 | Windows UIA、窗口与输入控制能力弱 | 不选 |
| C# + Node.js | 各自负责擅长领域，满足课程要求 | 需要跨进程契约 | 选择 |

边界固定：C# 负责 Windows 桌面执行，Node.js 负责任务编排、浏览器自动化、数据和管理台。

### ADR-002：Playwright 优先于纯鼠标操作浏览器

DOM 选择器可读、可等待、可断言，页面变化时也更容易诊断。纯坐标方式只用于证明底层输入能力，不作为购物主路径。

若站点明确阻止自动化或频繁触发风控，应更换演示站点或使用离线测试夹具，不绕过限制。

### ADR-003：FlaUI(UIA3) 优先于图像识别

UIA 能获取控件语义、状态和层级，比截图模板匹配更稳定。MVP 不引入 OCR/视觉模型，避免扩大依赖和测试范围。

只有目标控件不暴露 UIA 信息时，才允许加入受分辨率和 DPI 约束的锚点定位，并在每次点击前验证目标窗口。

### ADR-004：SQLite 优先于 PostgreSQL

系统首期只运行一台代理机、任务默认串行，SQLite 足以支持事务、持久化和查询。它减少部署工作，适合课程项目。出现多代理并发调度或远程部署需求时再评估 PostgreSQL。

### ADR-005：确定性工作流优先于自主 Agent

AI 输出存在不稳定和提示注入风险，因此 AI 只解析候选参数或生成摘要。动作顺序由代码定义，所有动作必须通过 Schema 和策略校验。首期不采用可自由调用工具的 ReAct/多智能体框架。

### ADR-006：本地单机部署优先

用户通过聊天工具远程发指令，控制服务无需公网暴露。单机部署也避免把账号会话、截图和自动化权限上传云端。

## 2. 主要风险登记

| ID | 风险 | 概率/影响 | 预防与缓解 | 止损条件 |
|---|---|---|---|---|
| R-01 | 微信控件不暴露稳定 UIA 属性 | 高/高 | M0 首先验证；固定版本；定位器集中管理 | 2 天内不能稳定收发时，改用另一可访问聊天工具或课程专用消息页 |
| R-02 | 微信无稳定消息 ID | 高/中 | 使用会话、发送者、规范化文本、时间窗口和可见顺序生成指纹；短期缓存去重 | 无法做到零重复时，任务执行前增加用户确认 |
| R-03 | 网站触发登录或验证码 | 高/高 | 使用专用测试账号；限制频率；人工接管 | 验证码频率导致成功率低于 80% 时更换演示站点 |
| R-04 | 页面改版导致选择器失效 | 高/中 | 语义选择器、Adapter 版本、每日 smoke、trace | 演示前冻结版本并准备本地测试页 |
| R-05 | 用户操作与 Agent 抢占鼠标 | 中/高 | 单任务串行、独占会话提示、前台窗口校验、紧急停止 | 无法提供独占桌面时只演示浏览器 DOM 路径 |
| R-06 | AI 输出错误或虚构 | 中/高 | 商品关键字段只从页面结构化提取；AI 不产生价格和链接 | AI 页面不可用时使用模板化比较，不阻塞商品查询 |
| R-07 | 持久化浏览器目录泄露登录会话 | 中/高 | 专用 OS 用户、目录最小权限、禁止打包上传、演示后清理 | 无法隔离账号时采用无登录查询 |
| R-08 | 网站条款不允许自动化 | 中/高 | 仅低频教学演示；查阅目标站点规则；不绕过风控 | 条款不允许时使用获准站点或自建测试页 |
| R-09 | 现场网络不稳定 | 中/高 | 离线测试夹具、录屏、预热浏览器 | 真实网络不可用时明确切换离线演示 |
| R-10 | 范围膨胀到通用 RPA | 高/中 | 只维护 AI 问答和商品查询两个工作流 | 新应用需求进入后续版本，不影响 MVP |

## 3. 开工前必须确认的产品决策

以下信息在任务书中缺失，不阻塞 M0 Spike，但必须在 M1 前冻结：

1. 目标聊天工具及确切版本，默认按 Windows 微信桌面端设计。
2. 目标 AI 页面和购物站点。
3. 代理机 Windows 版本、分辨率、DPI 和是否允许独占桌面。
4. 是否允许保存专用测试账号的本地浏览器会话。
5. 商品“最优”的评分权重及缺失字段处理方式。
6. 是否需要加入购物车；建议不纳入 MVP。
7. 管理台是否仅本机使用；建议首期仅本机。

截至 2026-09-24，仅使用 Fake/Stub 的 M1 跨平台工程代码已提前完成，上述产品决策仍
未冻结。该实现不接入真实应用，也不改变这些决策对 M0、真实 Adapter 开发和 M1
退出验收的阻塞关系。
